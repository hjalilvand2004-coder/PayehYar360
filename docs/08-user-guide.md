# سند ۰۸ — راهنمای کاربری پنل

پنل مدیریتی هسته مشترک روی آدرس `http://188.212.96.235:8094` در دسترس است. رابط کاملاً راست‌به‌چپ و فارسی است؛ تاریخ‌ها به وقت محلی (تهران) نمایش داده می‌شوند و تبادل زمان با سرور در UTC است.

## ورود

- در تولید، ورود از طریق پرتال یکپارچه SSO سازمان (`188.212.96.235:8086`) انجام می‌شود — هیچ گذرواژه‌ای در پنل ذخیره نمی‌شود.
- در محیط توسعه، پنل «ورود آزمایشی» نمایش داده می‌شود: شناسه کاربر، نام، کد مشتری (مثلاً `demo`) و نقش‌ها انتخاب می‌شوند.

## صفحات

| صفحه | کاربردها |
|---|---|
| **داشبورد** | سلامت هسته و دیتابیس، وضعیت RabbitMQ، رویدادهای Outbox (تعداد/سن)، فاصله (lag) مصرف‌کننده‌ها از مرجع، درخواست‌های اصلاح و پرونده‌های کیفیت معوق |
| **اشخاص** | جست‌وجو (نام یا فیلتر وضعیت)، ایجاد شخص، اصلاح با کنترل نسخه؛ کلیک روی سطر → جزئیات |
| **جزئیات شخص** | مشخصات + تب‌های شناسه‌ها (تأیید/ابطال توسط متولی)، تماس‌ها، حساب SSO (اتصال/قطع)، نگاشت‌ها، سابقه تغییر (change_log)؛ غیرفعال‌سازی با تأیید دوباره |
| **سازمان‌ها** | درخت سازمانی، ایجاد واحد و زیرمجموعه، جابه‌جایی/تغییر نام با کنترل نسخه؛ چرخه توسط سرور رد می‌شود |
| **اطلاعات پایه** | مجموعه‌های مرجع با نسخه؛ افزودن/اصلاح/بازنشستن آیتم با بازه اعتبار |
| **نگاشت شناسه** | ثبت نگاشت (نصب + شناسه محلی + انتخاب شخص با جست‌وجو)، پنل Resolve برای تبدیل شناسه محلی به شناسه مشترک، فهرست نگاشت‌ها |
| **مالکیت داده** | ماتریس مالکیت (موجودیت × گروه ویژه)؛ تغییر مالک فقط با نقش مجاز و ثبت ممیزی |
| **کیفیت داده** | کشف خودکار نامزدهای تکرار، ایجاد پرونده، مقایسه شواهد (شناسه‌ها و وضعیت تأیید)، انتخاب شناسه نهایی و ادغام با **تأیید دوباره**؛ سابقه ادغام و بازگردانی |
| **درخواست اصلاح** | فهرست به تفکیک وضعیت، مشاهده تغییر پیشنهادی، تأیید (اعمال خودکار با کنترل نسخه) یا رد با یادداشت |
| **اتصال‌ها** | نصب‌ها و حالت‌ها (یکپارچه/مستقل)، checkpoint و lag هر نصب، ایجاد Snapshot و دانلود خروجی، تطبیق پایه، ثبت نصب جدید |
| **ممیزی** | جست‌وجوی سوابق به تفکیک موجودیت/عملیات/عامل با مقادیر قبل/بعد و Correlation-Id — فقط خواندن |

## اصول نمایش

- هر رکورد **منبع، نسخه و آخرین تغییر** را نشان می‌دهد؛ فیلدهای غیرمالک فقط‌خواندنی‌اند.
- در تعارض نسخه (۴۱۲)، پیام راهنما ظاهر می‌شود و نسخه جدید باید بارگیری شود.
- عملیات حساس (ادغام، تغییر مالکیت، قطع حساب، غیرفعال‌سازی) همیشه تأیید دوباره می‌خواهند.
- کنترل نمایش بر اساس نقش‌هاست؛ کنترل واقعی در Backend انجام می‌شود.

## گردش‌کارهای رایج

**ثبت و اصلاح شخص:** اشخاص → ایجاد شخص → (شناسه/تماس در جزئیات) → اصلاح از فهرست یا جزئیات.

**رسیدگی به تکرار:** کیفیت داده → نامزدها → ایجاد پرونده → بررسی شواهد → انتخاب شناسه نهایی → تأیید دوباره → نگاشت‌ها منتقل و رویداد `PersonMerged` منتشر می‌شود.

**درخواست غیرمالک:** جزئیات شخص → (در صورت نداشتن نقش مالک) درخواست اصلاح ثبت شود → متولی در «درخواست اصلاح» تأیید/رد می‌کند؛ تأیید = اعمال خودکار.

**اتصال زیرسامانه جدید:** اتصال‌ها → ثبت نصب جدید (کد سامانه، کد نصب، حالت، scopeها) → مصرف‌کننده Snapshot می‌گیرد → تغییرات را با cursor دنبال و checkpoint ثبت می‌کند.
